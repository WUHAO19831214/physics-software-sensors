# 基准测试方案

## 1. 目标

基准测试回答四个不同问题，不能互相替代：

1. **契约正确性**：输出格式、状态和边界条件是否符合 Schema；
2. **算法质量**：与人工/仪器真值相比误差如何；
3. **运行性能**：在明确硬件环境下吞吐、延迟和资源占用如何；
4. **集成可靠性**：权限、设备中断、丢帧、停止和恢复是否可控。

## 2. 分层基准

| 层级 | 输入 | 是否需要硬件 | 主要用途 |
| --- | --- | --- | --- |
| L0 契约 | 合成 JSON/伪帧 | 否 | 每次提交 |
| L1 确定性回放 | 固定图像、视频、屏幕截图 | 否 | 算法回归与跨语言对照 |
| L2 受控实验 | 标定板、位移台、标准显示值 | 是 | 精度、重复性与失效边界 |
| L3 课堂/现场 | 实际设备和原软件 | 是 | 兼容性、稳定性、可用性 |

CI 只要求 L0 和可公开的小型 L1。L2/L3 结果通过签名报告进入仓库，不在普通 CI 中伪模拟通过。

## 3. 通用记录项

- 传感器 ID/版本、来源 commit、配置快照；
- 数据集 ID/版本和所有文件 SHA-256；
- OS、CPU/GPU、内存、Python/Node/浏览器、依赖与模型版本；
- 预热次数、重复次数、随机种子、线程数；
- 输入分辨率、帧率、颜色空间、ROI、样本量；
- 成功、丢失、降级、错误、丢帧数量；
- p50/p95/p99 延迟、实际吞吐率、峰值内存；
- 真值生成方式、标注者一致性和不确定度；
- 失败样本及原因，而不是只保留成功平均值。

## 4. 各传感器指标

### 摄像头/屏幕采集

- 实际 FPS、帧间隔 p50/p95、抖动；
- 丢帧率、重复帧率、首帧延迟、停止耗时；
- 请求分辨率与实际分辨率；
- 权限拒绝、流结束、窗口最小化/遮挡的状态行为；
- 端到端时间戳偏差（有外部参考时）。

### OCR 数字

- 完全正确率、数值 MAE/RMSE；
- 符号错误率、小数点错误率、拒绝率、误接受率；
- 不同缩放、字体、亮度、背景线、负数和零；
- OCR 原始误差与平滑/范围过滤后的应用误差分开报告；
- 平均与 p95 识别耗时、实测采样率。

### 颜色标记与光斑重心

- 静态位置 bias/RMSE、帧间标准差；
- 丢失率、误锁率、重捕获时间；
- 光照、曝光、背景干扰、尺寸、模糊、ROI 边缘分层结果；
- 动态轨迹位置误差与峰—峰范围误差；
- 物理换算另报标定误差，不与像素定位误差混合。

### YOLO 追踪

- 检测 precision/recall、mAP（数据集适用时）；
- MOTA/HOTA/IDF1、ID switch、track fragmentation；
- 各输入尺寸与后端的 FPS/延迟；
- 模型缺失/加载失败时回退后端的单独结果；
- 不能把 HOG 回退结果汇总为 YOLO 精度。

### 模板/单目标追踪

- bbox IoU、中心误差、成功率 AUC；
- 初始化成功率、丢失帧数、重捕获/重初始化时间；
- 尺度、旋转、遮挡、运动模糊和出画；
- CSRT/KCF/MIL 后端分别报告，不能只给聚合平均。

## 5. 默认统计方式

- 每个场景至少 3 次独立运行；受随机影响的模型建议 5 次以上；
- 同时报告样本数、均值/中位数、标准差或四分位距；
- 有参考真值时报告 95% 置信区间或一致性界限；
- 阈值必须在运行前写入协议，真实数据完成前不填猜测值；
- 基准结果不得因失败而丢行，失败作为结果的一部分。

## 6. 升级门禁

一个适配器从 `incubating` 升为 `candidate`，至少应满足：

- L0 契约测试全部通过；
- 固定 L1 回放数据上无未解释回归；
- 行为与来源实现完成黄金主对照；
- 许可证、模型和数据集卡完整；
- 已记录回退路径。

升为 `stable` 还需要目标设备上的 L2 验证、一个下游试点和连续版本兼容测试。具体数值门槛由每个传感器的基准协议预先设定。
