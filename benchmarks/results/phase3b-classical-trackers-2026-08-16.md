# Phase 3B Classical Tracker Replay — 2026-08-16

Evidence level: **synthetic/replay only**. This is source-compatibility and software-performance evidence, not real-experiment accuracy, physical displacement accuracy, or a device compatibility matrix.

Environment: macOS arm64, Python 3.12.13, OpenCV 4.14.0 contrib headless, NumPy 2.5.2. Machine-readable output: [JSON](phase3b-classical-trackers-2026-08-16.json).

## Spot centroid

The six PNG fixtures were generated by `examples/spot-centroid/generate_fixtures.py`. `tools/source_spot_centroid_harness.mjs` executed the fixed browser-source threshold and weighting equations to create the golden output; the Python extraction then consumed the same pixels.

| Metric | Result |
| --- | ---: |
| Detection/lost agreement vs source | 6 / 6 |
| Maximum centroid error vs source | 0.0 px |
| Defined comparison tolerance | 1e-9 px |
| Median processing latency (200 mixed fixture updates) | 0.793 ms |
| p95 processing latency | 0.875 ms |
| Median-derived throughput | 1260 fps |

The throughput figure is an in-process microbenchmark on 160×120 synthetic images; it must not be extrapolated to camera delivery rate, browser performance, high-resolution inputs, or experiment accuracy.

## Template / single-object tracker

`tools/generate_template_tracker_golden.py` imported `ObjectTemplateTracker` from the fixed source commit and generated seven scripted lifecycle cases: fallback initialization, movement, disappearance, update exception, reinitialization, post-reinitialization movement, and all backends unavailable. Stable numeric/status fields match at 1e-9 px in the Python tests; diagnostic error prose is intentionally not required to match Chinese source wording.

An additional real OpenCV synthetic replay initialized a textured target ROI and used the actual contrib backend factory.

| Metric | Result |
| --- | ---: |
| Source-executed scripted cases | 7 |
| Requested / selected backend | CSRT / CSRT |
| Synthetic moving frames tracked | 3 / 3 |
| Blank-frame lost state | correct |
| Maximum center error vs known synthetic target | 1.0 px |
| Sequence update median | 7.472 ms |
| Same-frame median / p95 (200 updates) | 7.722 / 9.577 ms |
| Median-derived throughput | 130 fps |

Fallback behavior is separately tested by making CSRT unavailable and KCF initialization fail; MIL is selected and `tracker-backend-fallback` is emitted. OpenCV tracker results are algorithm/version/platform sensitive, so source comparison uses lifecycle and stable output fields while the real-backend replay records its exact environment.

## Upgrade use

Future changes must rerun both golden suites and this replay. A candidate that changes centroid/bbox semantics, lost behavior, backend selection, or latency must record the reason and new tolerance in an upgrade record before replacing the current implementation.
